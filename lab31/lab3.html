2. Background: Retrieval-Augmented Generation

RAG combines parametric memory (knowledge in the pretrained model) with non-parametric memory (an external passage store), so the model can use retrieved data without extra pretraining.

  • Retriever: a Dense Passage Retriever that indexes passages in a low-dimensional continuous space.
  • Generator: a pretrained seq2seq transformer (originally BART-large) that conditions on the query x concatenated with the retrieved passage z.
  • Inference: Maximum Inner Product Search finds the top-K passages. The passage is a latent variable, and predictions are marginalized over it.

4. Part 2: RAG-Sequence vs RAG-Token (Q3 & Q4)

4.1 Concepts (Q3)

RAG-SequenceRAG-Token
FormulaΣz p(z|x) ∏i p(yi|x,z,y1:i-1)∏i Σz p(z|x) p(yi|x,z,y1:i-1)
MarginalizationSum over passages outside the product over tokensSum over passages inside the product
Passage useOne passage supports the whole output sequenceDifferent passages can influence different tokens

Per Lewis et al., RAG-Token did better on open-domain QA, because those questions often need facts from several passages. RAG overall gave more specific and accurate outputs than the parametric-only seq2seq models of the time.

4.2 Implementation (Q4)

  • log_sum_exp is the numerically stable helper: max + log Σ exp(x − max).
  • RAG-Sequence: sum token log-probs per passage, add the passage log-prob, then apply log-sum-exp across passages.
  • RAG-Token: at each token position, apply log-sum-exp across passages of (passage log-prob + token log-prob), then sum over positions.

5. Part 3: Memory and Long-Term Context (Q5)

The context window is a fundamental bottleneck for persistent memory and large knowledge bases, even with windows growing from 4K to over 1M tokens. Two strategies address it:

StrategyIdeaTrade-off
Long Context (LC)Extend the window so more tokens fit directlyAttention cost grows O(n²)
RAGRetrieve only relevant information from external storageDepends on retrieval quality

MemGPT borrows from operating systems. The context window is "main memory" (RAM) and external storage is "disk". The LLM pages information in and out through function calls, like virtual memory.

6. Review Notes and Issues Found

  1. Swapped explanation in the RAG-Token demo. The closing printout says "RAG-Sequence allows different passages to influence different tokens" and "RAG-Token commits to a single passage". That is backwards, because RAG-Token is the one that mixes passages per token. The code is correct; only the printed text is wrong.
  2. The two demos are not comparable. The RAG-Token cell says it uses "the same example data", but it uses different token probabilities from the RAG-Sequence cell. So −2.5526 vs −2.0667 says nothing about which model is better. The sequence and token probabilities should be computed on one matrix.
  3. SimpleDPR departs from real DPR. It uses one shared sentence-transformer (all-MiniLM-L6-v2) instead of two encoders. The docstring says embeddings come from [CLS], but this model mean-pools. The scores look like cosine similarity (normalized embeddings) rather than raw dot products. It also appends the literal text "[SEP]", which this model does not treat as a special token.
  4. chunk_document is not exercised. No cell calls it, so it is untested in the notebook.
  5. Q5 has no code. The notebook has duplicate Q5 / "Part 3" markdown, and the “Question 1” text largely repeats the Part 1 background. The numbering is inconsistent: Parts 1 and 3 exist but there is no Part 2, and the questions are labelled Q1–Q5.
  6. The summary mentions points the notebook never covers. It cites the advantages of dense over sparse retrieval and the O(n²) cost of attention, and neither is discussed earlier.

8. Key Takeaways

  • RAG gives LLMs access to external knowledge without retraining.
  • Dense retrieval matches on meaning rather than keywords, as the NLP and neural-network queries show.
  • RAG-Sequence favours coherence with a single source. RAG-Token favours multi-source synthesis.
  • Long-term memory needs a strategy (long context, RAG or hierarchical memory) because attention is expensive.
